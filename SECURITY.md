# Security Policy

## Reporting a Vulnerability

Please do not open a public issue for security vulnerabilities.

Use a [GitHub Security Advisory](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing/privately-reporting-a-security-vulnerability) (private vulnerability reporting) for this repository if enabled. If private reporting is not enabled, open a minimal issue asking for a contact without including exploit details, and a maintainer will follow up.

Include:

- A description of the issue
- Steps to reproduce (without live secrets)
- Affected version or commit

## Scope

This project analyzes public repositories only. It never executes repository code. Reports about API key exposure, input validation bypasses, or server-side request forgery are particularly welcome.

## Response

Maintainers will acknowledge reports as promptly as possible. As an early-stage volunteer project, there is no guaranteed SLA, but good-faith reports will be taken seriously.
